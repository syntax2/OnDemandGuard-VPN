| **Question**                                                 | **Sketch of Answer**                                                                                                                                                                |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. How does WireGuard perform key exchange?**              | Uses the **Noise IK** handshake: the server’s long-term key + client’s ephemeral key + optional PSK run through Curve25519 ECDH, then HKDF to derive session keys.                  |
| **2. Why choose WireGuard over OpenVPN/IPsec?**              | Much smaller codebase (∼4 KLOC), uses modern crypto primitives, in‐kernel module for performance, simple config (pubkey pairs instead of certs), faster handshakes.                 |
| **3. How does Terraform track infrastructure state?**        | It keeps a **state file** (`terraform.tfstate`): JSON mapping of resources ↔ real-world IDs. On `plan`, Terraform diffs this state vs. current cloud. You can back it up in S3.     |
| **4. How do you handle sensitive values in Terraform?**      | Mark outputs as `sensitive=true`; use environment vars or encrypted files (HashiCorp Vault, AWS SSM Parameter Store, or S3 with SSE-KMS); avoid hard-coding secrets in `.tf`.       |
| **5. What happens if someone manually changes a resource?**  | That’s called **drift**. On `terraform plan`, Terraform will detect differences between the real resource and state and will propose to “reconcile” (change it back).               |
| **6. Why use an Elastic IP for your VPN server?**            | So your VPN endpoint’s public IP never changes—clients can rely on a static `Endpoint = 1.2.3.4:51820`.                                                                             |
| **7. What’s a Security Group vs. NACL in AWS?**              | SGs are stateful, instance-level firewalls; NACLs are stateless, subnet-level. SGs auto-allow return traffic; NACLs require explicit inbound+outbound rules.                        |
| **8. How does IP forwarding and NAT work for a VPN server?** | You enable `net.ipv4.ip_forward=1` so Linux routes traffic between `wg0` and `eth0`, then use an `iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE` rule to NAT client traffic. |
| **9. How do you ensure your Terraform runs are idempotent?** | Always run `terraform fmt` and `terraform validate`; avoid inline random IDs; pin provider versions via `required_providers`; break resources into logical modules.                 |
| **10. How would you scale this VPN solution?**               | Introduce an **Autoscaling Group** + **Network Load Balancer**, use a launch template with the same WG bootstrap, store state in a shared Kubernetes ConfigMap or Consul.           |
